# Experiment Notes

実験設計、条件変更、アンケート項目、操作ログ項目などを整理するためのメモです。

## 実験用受付番号

有効な `task`、`color`、`yellow` がそろった実験アクセスでは、注文成立時に次の形式で受付番号を生成する。

`[正誤][条件][タスク]-[操作時間]-[総タップ数]-[誤選択回数]-[戻る回数]`

例：`TA1-065-024-01-02`

- 正誤は、最終注文が正解なら `T`、不正解なら `F`。
- 条件 `A` はパステル・黄変化なし。
- 条件 `B` はパステル・黄変化あり。
- 条件 `C` は高コントラスト・黄変化なし。
- 条件 `D` は高コントラスト・黄変化あり。
- タスクは `1` から `4`。
- 操作時間は内部ではミリ秒のまま保持し、受付番号の生成時に秒へ換算して四捨五入する。最低3桁で0埋めする。
- 総タップ数は最低3桁、誤選択回数と戻る回数は最低2桁で0埋めする。
- 最低桁数を超えた値は切り捨てず、そのまま必要な桁数で出力する。
- 数字部分は固定位置ではなく、ハイフン区切りで解釈する。
- 商品の正誤判定は商品IDとオプションIDを使用し、表示順には依存しない。

## 黄変化表示 v1

- 予備実験用の表示変換であり、70歳の視覚を正確に再現するものではない。
- モデルは基準20歳、対象70歳。参照LCDはColour Science for Python 0.4.7のApple Studio Display三原色スペクトル。
- CIE 1931 2度等色関数と参照LCDスペクトルを400–780nm、1nm間隔で使用する。水晶体TL1は400–650nmを10nm間隔から線形補間し、650nm超はTL1=0、400nm未満は対象外とする。
- Colour 0.4.7の実装では、等間隔の分光分布を既定でSprague補間、不等間隔をCubic Spline補間する。今回の参照LCDスペクトルと等色関数は等間隔データであり、`align()`で再標本化が必要な場合はSprague補間が使われる。範囲外は`align()`の既定外挿に依存するが、今回の計算範囲は凍結データの400–780nm内である。確認元はColour 0.4.7公式文書およびリリースノート（https://colour.readthedocs.io/en/latest/ 、https://github.com/colour-science/colour/releases/tag/v0.4.7）。
- sRGBを線形化し、次の行列を列ベクトルの線形RGBへ適用する。色域外成分は0–1へクリップしてからsRGBへ戻す。

```
[ 0.932675028852,  0.046440604984, -0.016148691713 ]
[-0.005685981497,  0.707416751687,  0.022443569675 ]
[-0.009362782733, -0.027474700634,  0.386341069418 ]
```

- HTML内のSVG `feColorMatrix`へ同じ係数を設定し、`color-interpolation-filters="linearRGB"`を明示する。
- 有効な`task`、`color`、`yellow`がそろい、`yellow=1`のときだけページ描画全体へ一度適用する。`yellow=0`と通常アクセスには適用しない。配色テーマとは独立している。
- 旧`filter-config.js`の黄色オーバーレイ設定は未使用だったため削除し、行列との二重適用経路をなくした。
- 瞳孔縮小、ぼけ、散乱、神経系、色順応は含まない。参照LCDからsRGBへ移したハイブリッド近似であり、人体での妥当性は未検証。
- 数量変更の`window.confirm()`は表示変換の対象外になるため、同内容のアプリ内モーダルへ置き換えた。従来はブラウザダイアログ内の確定・キャンセル操作を総タップ数へ含められなかったが、置換後はシミュレータ内の有効なボタン操作として1回加算する。数量の誤選択判定は確定時だけ実行し、キャンセルでは実行しない。
- iOS Safariで初回画面やsticky/fixed領域が未変換になる症状への対策として、共通ルート`#app`の内容を描画した後に同じフィルターを再解決する。`-webkit-filter`も同じURLへ指定する。子要素にはフィルターを追加しない。
- WebKitでは、SVGフィルターを持つ親の下でアニメーションや`will-change`により独立合成された子がフィルターから外れる既知事例があるため、画面遷移は`transform`と`will-change`ではなく、同じ位置変化を`left`で行う。黄変化行列の係数や適用回数は変更しない。
- `left`による画面遷移は`transform`よりレイアウト・描画負荷が増える可能性があり、操作時間へ影響し得る。Safari実機で黄変化の適用漏れが解消したと確認できるまでは暫定対策として扱い、本番前に遷移性能も確認する。
- `debug=1`のときだけ、ビルド識別子、実験設定、画面名、計算済みfilter、SVG参照、JavaScriptエラーと診断色パッチを表示する。診断パネルは`#app`の外に置くため黄変化フィルターの対象外である。
- iOS Safari実機では、最小診断ページは変換される一方、本体ホームの初回描画、カテゴリのsticky領域、複数の画面遷移で適用漏れ・一時的な解除が確認された。スクロール後にホームへ変換が現れる場合もある。原因は確定しておらず、SVG行列全体の非対応とは扱わない。
- `debug=1&diag=...`で候補を一つずつ比較できる。`category-static`はカテゴリのstickyだけを解除、`bottom-nav-nonfixed`は下部ナビのfixedだけを解除、`animation-off`は画面遷移アニメーションだけを省略、`visual-wrapper`は`#app`ではなく単一描画ラッパーをフィルター対象にする。`panel-off`は外側の固定診断パネルだけを非表示にする。これらは診断専用で通常アクセスには適用しない。
